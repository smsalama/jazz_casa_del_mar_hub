# ADR-0005: Admin portal as a React application over a JSON API defined by the OpenAPI contract, with rich text stored as allow-listed JSON

- Status: Proposed (for T2)
- Date: 2026-10-15
- Author: System Architect (P4-T2)
- Requirements: FR-32 to FR-46 (built parts), NFR-1 to NFR-5, NFR-24, NFR-25, NFR-29 (admin from 768 px); threat model section 9 ("Rich text sanitiser"), TM-09, TM-30, TM-31, TM-32, TM-45, TM-50; RSK-22, RSK-36

## Context

The admin portal is English only, may require JavaScript (NFR-13), must meet WCAG 2.2 AA including keyboard use, focus, timeouts with warnings and accessible authentication (NFR-1 to NFR-5), and edits rich text in four languages that must pass an allow-list sanitiser on save for every language value and be encoded on render (NFR-24, G-7). The hub's `contract/openapi.yaml` is the source of truth for every endpoint, and the web repo generates its typed client from it.

## Options considered

1. **Server rendered admin pages** in Astro, with forms posting back. Works without JavaScript, but the editing experience for four language rich text, drag free reordering, media pickers and unsaved change warnings needs client code anyway.
2. **A React single page application** served from an `/admin` shell page and talking to `/admin/api/*` JSON endpoints, using the generated typed client.
3. **A separate admin application in its own repo or process.** Rejected with ADR-0001 and ADR-0013.

For rich text:

a. Store HTML from the editor and clean it with an HTML sanitiser (sanitize-html, or DOMPurify with a server side DOM).
b. Store the editor's **document JSON** (ProseMirror format from Tiptap) and validate it on the server against a strict allow-list schema; render it with our own component. HTML is never parsed on the server and never stored.

## Decision

**Option 2 with rich text option b.**

Application:

- `GET /admin` and `GET /admin/{path}` return a small shell page from Astro. It loads one bundled module that mounts React 19.3.0 with `createRoot`. It is not an Astro island, so there is no inline script (ADR-0002, ADR-0008).
- Routing inside the portal: React Router 8.4.0 (declarative mode).
- Accessible building blocks: React Aria Components 1.21.1 (dialogs, menus, list boxes, tabs, drag free reordering with move up and down buttons, toasts announced politely), so keyboard, focus and screen reader behaviour comes from a maintained library rather than hand built widgets.
- API calls: `openapi-fetch` 0.17.0 with types generated by `openapi-typescript` 7.13.0 from the contract (`npm run contract:types`). Hand written request or response types for contract shapes are not allowed (web repo `CLAUDE.md`).
- Generic field editors driven by the `ContentField` descriptors from the API (ADR-0004): each field shows the four languages together with a completeness indicator (FR-37).
- Unsaved change warning on leaving an edit screen (FR-38) via React Router's blocker and `beforeunload`.
- Session timeout warning two minutes before the idle limit, with an "extend" action (`POST /admin/api/session/extend`) (NFR-5).

Rich text:

- Editor: Tiptap 3.31.4 (`@tiptap/react`, `@tiptap/pm`, `@tiptap/starter-kit` with everything except paragraph, bold, italic, bullet list, list item and text disabled, plus `@tiptap/extension-link` with `protocols` limited to `https`, `http`, `mailto`, `tel` and `autolink` off). `injectCSS: false`, because Tiptap's injected `<style>` element would be blocked by the CSP; its few rules go in the admin stylesheet.
- The server accepts only this JSON shape (`RichTextDoc` in the contract): `doc` containing `paragraph` and `bulletList`; `bulletList` containing `listItem`; `listItem` containing `paragraph`; `paragraph` containing `text` nodes; `text` with optional marks `bold`, `italic`, `link`; `link.attrs.href` parsed with the WHATWG URL parser and allowed only for `https:`, `http:`, `mailto:` and `tel:`; text with Unicode category Cf removed except soft hyphen (U+00AD); limits on depth (3), nodes (2,000) and characters per field. Anything else (unknown node or mark, extra attributes, other schemes) is rejected with HTTP 422 naming the field and language; nothing is silently kept.
- This schema check **is the allow-list sanitiser** that NFR-24 requires: it runs on save for every language value, on the server, with the same code for all four languages. It is stricter than an HTML sanitiser because there is no HTML parser to confuse (no mutation XSS, no parser differential). Public rendering then builds elements from the JSON with escaping (encoding on render). This answers threat model section 9 ("a maintained allow list sanitiser that runs on the server; same library for all four languages") with a schema validator (Zod) instead of an HTML sanitiser library; the Security Engineer reviews this at the security architecture review.

Access control (NFR-25):

- Every `/admin/api/*` handler is wrapped by one `requireAdmin` guard that checks the session (401 when missing) and, for every method other than GET, the CSRF token (ADR-0006). Routes are deny by default: the guard runs in middleware for the whole `/admin/api/` prefix, and an unknown route returns 404 after the guard.
- `GET /admin/*` pages: middleware redirects to `/admin/sign-in` without a valid session, so no screen is shown signed out (FR-32). Until the first Administrator exists every admin request is refused with a "setup required" page or `403 setup_required` (FR-47, G-1).
- Record identifiers are random (UUID version 7 for internal ids); a missing record returns 404; every record request is checked for sign in (NFR-25).
- Enquiry, subscriber and media metadata are shown as text through React, which escapes by default; `dangerouslySetInnerHTML` is banned by lint (G-8, TM-09).
- One role (OQ-1). The guard takes a role argument so that the Editor role can return before real personal data exists (threat model note after section 8) without touching every handler.

## Consequences

- The admin bundle (React, React Aria, Tiptap, the router) is roughly 250 to 350 KB compressed. It loads only under `/admin`, never on public pages, so NFR-7 is unaffected.
- The contract describes the full admin surface; contract tests check every handler's responses against it (ADR-0012).
- Pasting formatted text from a word processor produces only the allowed formatting, because Tiptap drops unknown structure on paste and the server rejects anything outside the schema.
- If the security review insists on an HTML sanitiser library, sanitize-html (MIT) can be added in front of rendering without changing storage.
